# mp3fy agent instructions

This file is the repository-level operating procedure for Codex/agent work. Treat the user's feature or bug description as the product request; follow the release process below automatically when the request requires a build or release.

## Development and safety

- Preserve the user's library, playback state, Wrapped history, and backup files. Never run `adb uninstall`, `adb shell pm clear`, or any equivalent data-clearing command unless the user explicitly asks for it.
- Do not delete or overwrite the user's real MP3 files, selected folders, or `mp3fy-wrapped.json`. Temporary inspection dumps and host-side test files created by the agent must be removed before handoff.
- Inspect the existing implementation and reproduce the reported behavior before changing code. Fix the underlying cause instead of adding retries, delays, or extra loading states without evidence.
- Keep generated native output under `android/` out of commits; it is regenerated by Expo and ignored by Git.

## Release procedure

When a feature or bug fix is requested as a build/release:

1. Implement the change and add or update focused regression tests.
2. Bump both release identifiers in `app.json`:
   - `expo.version` (the human-readable version, e.g. `1.6.28`)
   - `expo.android.versionCode` (increment the integer)
3. Run validation before packaging:

   ```powershell
   npx tsc --noEmit
   node --experimental-sqlite --test tests/*.test.cjs
   git diff --check
   ```

4. Commit all source, test, and configuration changes first. The source commit must exist before the APK is built.
5. Stop stale Gradle daemons, regenerate native Android code, and build the optimized release APK:

   ```powershell
   .\android\gradlew.bat --stop
   npx expo prebuild --platform android --no-install
   Push-Location android
   .\gradlew.bat assembleRelease
   Pop-Location
   Copy-Item android\app\build\outputs\apk\release\app-release.apk mp3fy.apk -Force
   ```

   If Expo reports an `EBUSY` lock while clearing `android/`, stop only Java/Gradle processes and rerun prebuild; do not delete user data.

6. If an ADB device is connected, install the new APK in place without clearing data:

   ```powershell
   adb install -r -d mp3fy.apk
   adb shell dumpsys package com.anonymous.mp3fy | Select-String 'versionName=|versionCode='
   ```

   If no device is connected, still leave the built `mp3fy.apk` at the repository root and report that installation was skipped. Android Play Protect may show a scan prompt for locally sideloaded APKs; do not disable Play Protect globally.

7. Smoke-test the changed behavior on the installed app. For storage, backup, playback, or crash fixes, use a cold launch where relevant, inspect `adb logcat`, and verify the actual persisted result rather than relying only on the UI.
8. Commit the root APK separately from source changes, for example:

   ```powershell
   git add mp3fy.apk
   git commit -m "Package <version> <short feature name> APK"
   ```

9. Verify `git status --short` is clean, record the APK SHA-256, and remove every temporary file created on the host or device (including `/sdcard/*.xml` UI dumps and pulled test JSON files).

## Handoff requirements

The final report should include the version/versionCode, source commit, APK commit, APK hash, whether the phone was updated, tests run, on-device smoke-test result, and any limitation such as no connected device. Explain the diagnosed root cause and the durable fix, not just the symptom-level UI change.
